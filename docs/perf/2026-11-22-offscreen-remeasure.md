# 画面外のアニメ停止の測り直し（#12、PR #148）

PR #149 の測定は範囲が重なり、効いたかどうか言えなかった。往復を6回に増やして測り直した。

## 条件

- 道具は `scripts/bench-crowd-webkit.ts`（headless の WebKit）。窓は 1440×900、deviceScaleFactor 2。
- 町は60体、全員が作業中。画面内のカードは10体、画面外は50体。
- 計測は、ならし15秒のあと30秒。値は ps の CPU 時間の差で、単位は秒。
- before は 1068cfd、after は 80c3789。差は PR #148 だけ。`git diff --stat 1068cfd 80c3789` で確かめた。
- before と after を交互に6往復（各6回）。after では `data-offscreen` が50体に付いた（before は0）。
- 生の値は `2026-11-22-offscreen-remeasure.jsonl`。

## 結果（中央値、括弧は最小から最大）

| プロセス | before | after |
| --- | --- | --- |
| WebContent | 0.43（0.42〜0.49） | 0.485（0.37〜0.56） |
| ui | 1.355（1.30〜1.53） | 0.76（0.71〜1.09） |
| gpu | 0.05 | 0.045 |
| net | 0.08 | 0.08 |
| 合計 | 1.925（1.85〜2.11） | 1.365（1.18〜1.78） |

## 読み取れること

- WebContent の CPU は変わらない。after のほうがわずかに高いが、範囲が重なり、差とは言えない。
- ui プロセスの CPU は、after で約44%減った。範囲も重ならない。合計も約29%減った。
- ui の値は、PR #148 の入れる前後で変わった唯一の項目。

## 分かっていないこと

- headless の WebKit の ui プロセスが、アプリ（Tauri の WKWebView）では本体のプロセスに当たるかは未確認。当たるなら、減ったのは本体の CPU になる。
- なぜ WebContent ではなく ui が減ったかは未調査。
- 足踏み（fc-step）は測っていない。
- 開発版での測定、見た目の確認は未実施。

# アプリの大きさと起動の時間（#16）

2026-11-13 に、リリースビルドの .app（`bun tauri build --bundles app`、開発版の設定）で測った。Apple M5。直す前は feat/app-v1 の 8f4331c、直した後は perf/app-size-16。

## 大きさ

| | 直す前 | 絵だけ直した版（A） | この PR（B） |
|---|---|---|---|
| .app（`du -sk`） | 6,696KB | 6,196KB | 6,196KB |
| 実行ファイル（`Contents/MacOS/family-computing`） | 6,657,088 バイト | 6,145,216 バイト | 6,145,216 バイト |
| `public` の合計 | 862,933 バイト（228 ファイル） | 346,072 バイト（174 ファイル） | 同じ |
| `public/sprites/ninja` | 677,593 バイト | 160,732 バイト | 同じ |
| 起動のときに読む JS（`vite build`） | 812.58KB（gzip 233.58KB） | 同じ | 364.79KB（gzip 118.77KB） |
| ターミナルを開くときに読む JS | なし（起動の JS に入っている） | 同じ | 449.62KB（gzip 115.80KB） |

- .app の中身は、ほとんどが実行ファイルで、画面の JS と public の素材はその中に入っている。public を 516,861 バイト減らし、実行ファイルは 511,872 バイト減った。
- B は JS を2つに分けただけなので、.app の大きさは A と同じ。

## 起動の時間

`scripts/bench-startup.sh` で測った。.app の実行ファイルを起動する直前の時刻から、モック（`scripts/mock-ccn-crowd.ts`、承認待ち20体）が最初の `/api/sessions` の要求を受けるまでの時間を「起動から一覧の要求まで」とする。画面の JS が動いて、町を取りに来るまでの時間になる。窓が描かれた時刻ではない。本人が全画面のアプリを使っていると窓は隠れるが、JS は動くので要求は来る。

| | 回数 | 起動から一覧の要求まで（中央値） | 範囲 | 起動の10秒後の本体の RSS |
|---|---|---|---|---|
| 直す前 | 6 | 461ms | 434〜644ms | 104〜105MB |
| 絵だけ直した版（A） | 6 | 464ms | 429〜521ms | 104〜105MB |
| この PR（B） | 6 | 440ms | 421〜490ms | 103〜105MB |

3通りを、直す前、A、B の順に2回ずつ、3巡して測った（ロックは1回で取った）。記録は `docs/perf/2026-11-13-app-size-startup.jsonl`。B の中央値は直す前より 21ms 短いが、範囲が重なっていて、回ごとのばらつきより小さい。起動の時間がはっきり速くなったとは言えない。起動の時間の大部分は、本体と WebKit のプロセスを立ち上げる時間とみている（確かめていない）。

## 決めたこと

- キャラの PNG は、前向きの1列だけに切り出すことをしなかった。切り出すとさらに 79KB 減るが、`src/kid/avatar.css` の `.fc-body img` と `src/App.css` の `.fc-deadimg.fallback` の幅（`* 4`）を変えることになる。avatar.css は #12 の続きで別の子が変えている途中なので、重ならないようにした。
- 55体の絵を1枚のスプライトシートにまとめることもしなかった。色のプロファイルを外した後は、1枚あたり 259〜2,545 バイト（164枚で 151,664 バイト）で、まとめて減る分は小さい。まとめると Avatar の描き方を変えることになる。
- JS の依存に、使っていないものは無かった。`@tauri-apps/plugin-opener` は今の src では使っていないが、PR #39（URL をブラウザで開く）が使うので残した。
- ターミナル（`src/term/TerminalView.tsx`、xterm と WebGL の addon）は、起動のときに読まず、町を出した2秒後に先に読むようにした。起動の時間の差はばらつきの中だったが、起動のときに解く JS は 812KB から 365KB に減る。最初にターミナルを開くときに待たないよう、先に読んでおく。headless の WebKit で、町が出た時点ではターミナルの JS を読んでおらず、2.2秒後に読み、タブを押すと xterm が出ることを確かめた。
- Cargo の release の設定は、すでに Tauri の推奨（lto、codegen-units=1、strip、panic=abort）になっていたので変えていない。

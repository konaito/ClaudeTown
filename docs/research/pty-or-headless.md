# どのセッションを PTY で立てるか（#13）

2026-11-13 に、同じ依頼を画面なしと PTY の claude に出して、CPU とメモリを比べた。その数字から、PTY で立てるのは人が操作する根のセッションだけにし、子と孫は画面なしで立てることを提案する。採るかは本人が決める。

## 提案（本人の判断待ち）

- 「＋ 新しい世帯」で立てる根のセッションは、今までどおり PTY（`terminal: true`）で立てる案。人が右パネルのターミナルで打つため。
- 親のセッションが ccn の create_session で作る子と孫は、`terminal` を付けずに画面なし（ccn の node のセッション、kind node）で立てることを勧める。
- 人が子や孫のターミナルを見たいときだけ、その子を `terminal: true` で立てる案。依頼文に「ターミナルで見たい」などとあるときに限る。
- 画面なしの子と孫は、Claude Town の右パネルでチャットの欄だけを出す案。ターミナルのタブは出さない（今の App.tsx の `hasTerm` のとおりで、コードの変更は要らない）。承認は右パネルの「許可する」「拒否する」で答える。

勧める理由は3つある。
1. 返事を書いている間の claude の CPU 時間は、PTY が画面なしの約1.8〜2.1倍だった（下の表）。claude が端末の画面を描き続けるため。子と孫を全員 PTY で立てると、人が見ていない子の分まで、この負荷が人数分かかる。
2. claude の RSS は、PTY が約50〜70MB 多かった。30本なら 1.5〜2.1GB になる。
3. 画面なしでも、Claude Town で見せたいもの（会話、承認、状態）は全部出せる。ccn の node のセッションは、messages の口で会話を読め、permissions の口で承認に答えられる。

## 比べた数字

`claude --model haiku` に「1から N までの整数を、1行に1つずつ、数字だけで書いて。道具は使わない。」を1回だけ出した。返事が終わるまでの claude の木の CPU 時間と RSS を `ps` で取り、その後の20秒の待機も測った。

- 画面なし: ccn の node のセッションと同じ入出力にした（`claude -p --input-format stream-json --output-format stream-json --verbose`）。ccn は Agent SDK の `query()` で claude を動かしていて、SDK はこの形で claude を起動する
- PTY: bun の `Bun.spawn(cmd, { terminal: { cols: 120, rows: 40 } })` の中で、対話モードの claude を動かした（ccn の pty-driver と同じやり方）
- 共通: `--strict-mcp-config`（MCP サーバーを起動しない）、`--settings '{"disableAllHooks":true}'`（hook を動かさない）、`--session-id`。作業ディレクトリは `/tmp/ct-anim/pty13/work`
- 返事の終わりは、会話の記録（jsonl）で、最後の assistant が `end_turn` で本文の最後が N になった時点とした（N=400 の回は、記録で最後まで書いたことを後から確かめた）
- 機械は Apple M5、claude 2.1.322。計測の間、ほかの子は開発版と計測を止めていた（共有のロック）。load は 2.9〜6.6

- 返事を書いている間の CPU 時間は、N=400 で 1.59秒と 2.93秒（PTY が約1.8倍）、N=1500 で 1.82秒と 3.85秒（約2.1倍）だった（各2回の平均）。
- RSS は、N=400 で 325MB と 377MB（+52MB）、N=1500 で 355MB と 424MB（+69MB）だった。
- 返事の後の待機は、どちらも20秒で 0.3〜0.5秒（1コアの約2%）で、差が無かった。PTY はステータス行の更新で20秒に 59〜267B を出し続けた。
- PTY の出力は、画面の差分だけなので、N=400 では画面なしより少なかった。N=1500 では同じくらいになった。

## 測っていないこと

- ccn のノードの側の負荷。PTY のセッションでは、ノードが claude の出力を受けて末尾を覚え、画面の口に流す。2026-11-12 の実測（#13 の本文）では、出力中の PTY の claude が1体あると、ノードの CPU が待機の約7%から約12.6%に上がった。画面なしのセッションでは、ノードは JSON の行を受けて会話にするだけになる。今回は claude の木だけを測った。
- MCP サーバーと hook を動かしたときの数字。どちらの方式でも同じだけ起動するので、差には効かない見込み（未検証）。
- 長い作業（道具を何度も使う、数分以上の返事）。依頼は数字を書くだけの1往復にした。
- 回数は各条件2回ずつで、ばらつきは見ていない。

## 案を採るときに変えるもの

- ccn のコードは変えなくてよい。create_session の `terminal` は省けば画面なしになる。
- 子を作る側の指示（本人の `~/.claude/CLAUDE.md` の「ccn(local) は … `terminal` に true … を渡します」）を直す必要がある。今の指示では、子は全員 PTY で立つ。

family-computing キャラ素材の見本（Ninja Adventure と Noto Animated Emoji）

2026-11-12 作成。素材は public/sprites/ninja と public/sprites/noto に置いたファイルを読み込んでいる。案の並び順に意味はない。

選ぶときに見るところ
  1. 6つの状態を、20〜30体の中で一目で見分けられるか。下の「20体の見た目」で比べる。
  2. 「家族の子供たちが働いている」に見えるか。キャラ本体があるのは案 A と C、顔だけなのは案 B。
  3. 表示の重さとファイルの大きさ。Noto の形式ごとの測定は下の表にある。Ninja は1体あたり数 KB の PNG。

案 A、B、C と状態の対応

各行の絵は実物のファイルを 64px で表示している。Ninja のキャラは Boy。

20体の見た目（白い背景）

状態の割合は仮置き（はたらいてる8、あなたの番3、まってる3、おわった2、ひとやすみ3、エラー1）。A と C は 64px、B は 56px。

単位はバイト。Lottie は再生に lottie-web（lottie_light.min.js 5.12.2 は 168,236 バイト）が別に要る。Ninja の PNG は 1枚 1KB 未満から数 KB で、95キャラと Emote 30個で public/sprites/ninja 全体が 4.7MB（CharacterAnimated の GIF を含む）。

WKWebView（macOS の Tauri と同じ部品）での表示

Swift で WKWebView を1枚だけ開く小さなプログラムを作り、bench.html に30体を並べて14秒後にスナップショットを撮った。ページはローカルの HTTP サーバーから配った（file:// では lottie-web が JSON を読めなかったため）。

CPU 使用率（WKWebView の各プロセスの CPU 時間を8秒間で割った値。file:// で1回、HTTP で3回。Lottie は HTTP の3回のみ）: GIF 0.8〜15.6%、WebP 0.4〜17.8%、AVIF 0.4〜11.0%（file:// で測った1回目は 392%）、Lottie 0.1〜0.6%、Ninja 0.4〜4.1%。回ごとのぶれが大きく、形式の間の差は言い切れない。AVIF の1回目を除き、どの回も 18% 以下だった。
